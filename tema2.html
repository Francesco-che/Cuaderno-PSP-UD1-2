Guía paso a paso para plantear problemas de examen, elegir el mecanismo adecuado (synchronized, Semaphore, ReentrantLock), evitar condiciones de carrera y romper Deadlocks.

Regla de Oro de Concurrencia

1. Separa Actores (Runnable) de Recursos (Monitores).

2. wait() / await() SIEMPRE dentro de while.

3. unlock() / release() SIEMPRE en finally.

Paso 0 · Antes de escribir una línea

Cómo plantear cualquier ejercicio de hilos en 4 preguntas

1

Identifica Actores vs. Recursos

Actores (Hilos): Quienes ejecutan acciones (Robot, Cliente, Filosofo). Implementan Runnable.
Recursos (Pasivos): Objetos compartidos que guardan datos (Cuenta, Cinta, Central). No son hilos.

2

Detecta la Sección Crítica

¿Qué variable o array leen y modifican varios hilos a la vez? (ej. saldo, contador++, estaciones[]). Ese trozo de código debe ejecutarse en exclusión mutua para evitar Race Conditions.

3

Elige la Herramienta

• 1 en 1 simple: synchronized.
• Aforo de N plazas: Semaphore(N).
• Esperar condición (lleno/vacío): wait()/notifyAll() o ReentrantLock + Condition.

4

Orquesta en el Main

1. Crea una única instancia del recurso compartido.
2. Pásala por constructor a todos los hilos.
3. Arranca con .start() y espera al final con .join().

Mecanismo ¿Cuándo usarlo en el examen? Liberación Salas de espera
synchronized + wait/notifyAll Exclusión mutua básica (1 hilo) o pausar/reanudar hilos bajo una condición booleana (ej. alerta). Automática 1 única cola por objeto
Semaphore(1) (Mutex) Igual que synchronized (1 hilo a la vez), cuando piden un semáforo binario explícito. Manual (finally) Cola de permisos
Semaphore(N) (Contador) Controlar el aforo máximo de N plazas idénticas (3 estaciones, 4 cajas, 5 conexiones). Manual (finally) Cola de permisos
ReentrantLock + Condition Productor-Consumidor con 2 colas separadas (lleno/vacío), colas de prioridad o intentos sin bloqueo (tryLock). Manual (finally) Múltiples (newCondition)
Fundamentos

2. Creación de Hilos (Runnable), Ciclo de Vida y Métodos Base

Estructura Estándar (Implementando Runnable)

Es la forma recomendada frente a extends Thread porque separa la tarea del hilo y permite heredar de otra clase. 

// 1. Clase Tarea (Actor)
public class Trabajador implements Runnable {
    private final RecursoCompartido recurso; // Referencia compartida

    public Trabajador(RecursoCompartido recurso) {
        this.recurso = recurso;
    }

    @Override
    public void run() {
        try {
            while (!Thread.currentThread().isInterrupted()) {
                recurso.hacerTrabajo();
                Thread.sleep(500);
            }
        } catch (InterruptedException e) {
            // Salida limpia cuando Main llama a interrupt()
            Thread.currentThread().interrupt();
        }
    }
}

// 2. En el Main
RecursoCompartido recurso = new RecursoCompartido();
Thread h1 = new Thread(new Trabajador(recurso), "Hilo-1");
h1.start(); // ¡SIEMPRE start(), NUNCA run()!
h1.join();  // Main espera a que h1 termine

Diccionario de Métodos de Thread

t.start()

Crea un nuevo hilo real en el SO y llama a run() en paralelo. Si llamas a t.run() directamente, se ejecuta secuencialmente en el hilo main (error grave de examen).

t.join()

El hilo que llama (normalmente main) se queda bloqueado esperando hasta que el hilo t muera. Imprescindible antes de imprimir totales finales.

Thread.sleep(ms)

Duerme al hilo actual durante ms milisegundos (estado TIMED_WAITING). No libera candados si los tenía cogidos.

t.interrupt() & isInterrupted()

Envía una señal de parada al hilo t. Si está en sleep(), wait() o acquire(), lanza InterruptedException permitiendo un cierre limpio.

t.setDaemon(true)

Marca el hilo como demonio (segundo plano, ej. sensor o log). Se debe llamar antes de start(). Cuando acaban los hilos normales, la JVM mata los demonios automáticamente.

Palabra clave volatile

Obliga a leer y escribir una variable directamente desde la memoria RAM principal y no desde la caché de la CPU (ideal para flags boolean o estados leídos por un Dashboard).

Monitores Nativos de Java

3. synchronized, wait(), notify() y notifyAll()

💡 ¿Cómo razonarlo?

Todo objeto en Java tiene un candado intrínseco (monitor). Al poner synchronized en un método o bloque, solo un hilo puede poseer la llave de ese objeto a la vez. Si además necesita esperar a que otro hilo cambie un estado, usa wait() para soltar la llave y dormirse sin gastar CPU.

wait()

1. Suelta el candado del monitor.
2. Pone el hilo a dormir (WAITING).
3. Al despertar, recupera el candado antes de seguir. Solo puede llamarse dentro de un bloque synchronized.

notify()

Despierta a un único hilo elegido al azar entre los que estaban dormidos en el wait() de ese objeto. Peligroso si hay varios tipos de hilos esperando.

notifyAll()

Despierta a TODOS los hilos dormidos en ese objeto. Cada uno volverá a comprobar su bucle while de uno en uno. Es la opción más segura en exámenes.

▶ Ejemplo Real: Parada de Emergencia (Patrón SupervisorCentral) while + wait() + notifyAll()

Por qué while y no if: Por los spurious wakeups (despertares espontáneos del SO). Si un hilo se despierta por error, el while le obliga a re-comprobar si alertaActiva sigue siendo true antes de continuar. 

public class SupervisorCentral {
    private boolean alertaActiva = false;

    // Los trabajadores llaman a este método antes de operar
    public synchronized void verificarEstado() throws InterruptedException {
        while (alertaActiva) {
            wait(); // Suelta el monitor y se duerme hasta recibir notifyAll()
        }
    }

    // Activa la emergencia (los siguientes hilos que verifiquen quedarán pausados)
    public synchronized void activarAlerta() {
        this.alertaActiva = true;
    }

    // Desactiva la emergencia y despierta a TODOS los hilos pausados a la vez
    public synchronized void desactivarAlerta() {
        this.alertaActiva = false;
        notifyAll(); // Si usáramos notify(), solo despertaría a 1 robot y los demás quedarían colgados
    }
}
java.util.concurrent.Semaphore

4. Semaphore: Binario (Mutex) y Contador (Aforo N)

Constructores de Semaphore

• new Semaphore(1) → Mutex / Binario: Solo 1 hilo pasa a la vez (exclusión mutua estricta).

• new Semaphore(N) → Contador: Permite entrar hasta N hilos simultáneamente (ej. 3 estaciones de soldadura).

• new Semaphore(N, true) → Justo (Fair): Respeta el orden FIFO de llegada (el que más lleva esperando entra primero).

Métodos Principales

• acquire(): Pide 1 permiso. Si permisos > 0, resta 1 y entra. Si es 0, bloquea al hilo hasta que alguien libere.

• release(): Devuelve 1 permiso (suma 1) y despierta a un hilo en espera. ¡Siempre en finally!

• tryAcquire(): Intenta coger permiso sin esperar. Devuelve true si pudo, o false al instante si está lleno.

• availablePermits(): Devuelve cuántos permisos quedan libres actualmente.

▶ Ejemplo Real: Control de Aforo + Array Protegido + Mutex Semaphore(N) + Semaphore(1)

Trampa clásica de examen: Un Semaphore(3) limita cuántos entran (3), pero si además necesitas asignar qué índice exacto del array (0, 1 o 2) ocupa cada hilo, debes proteger la búsqueda en el array con synchronized para que dos hilos no cojan el índice 0 a la vez. 

import java.util.concurrent.Semaphore;

public class CentralSoldadura {
    // 1. Semáforo CONTADOR: permite 3 robots soldando en paralelo
    private final Semaphore semaforoEstaciones = new Semaphore(3);
    private final boolean[] estacionesOcupadas = new boolean[3];

    // 2. Semáforo BINARIO (Mutex): solo 1 robot firma en el tablero a la vez
    private final Semaphore mutexRegistro = new Semaphore(1);
    private int cochesRegistrados = 0;

    public int entrarEstacion() throws InterruptedException {
        semaforoEstaciones.acquire(); // Pide plaza (si hay 3 dentro, espera aquí)
        return asignarIndiceLibre();  // Busca qué plaza física (0, 1 ó 2) está libre
    }

    private synchronized int asignarIndiceLibre() {
        for (int i = 0; i < estacionesOcupadas.length; i++) {
            if (!estacionesOcupadas[i]) {
                estacionesOcupadas[i] = true;
                return i;
            }
        }
        return -1; // Obligatorio para que compile Java (nunca ocurre gracias al Semaphore)
    }

    public void salirEstacion(int numEstacion) {
        liberarIndice(numEstacion);     // 1º Marcamos el array como libre
        semaforoEstaciones.release();   // 2º Devolvemos el permiso al semáforo
    }

    private synchronized void liberarIndice(int numEstacion) {
        estacionesOcupadas[numEstacion] = false;
    }

    public void firmarCertificado() throws InterruptedException {
        mutexRegistro.acquire(); // Exclusión mutua de 1 en 1
        try {
            cochesRegistrados++;
            Thread.sleep(200);
        } finally {
            mutexRegistro.release(); // Pase lo que pase, liberamos el mutex
        }
    }
}

5. ReentrantLock, tryLock() y Condition

Métodos de ReentrantLock

• new ReentrantLock(boolean fair): Si fair = true, entrega el candado por estricto orden de llegada (FIFO).

• lock(): Coge el candado o duerme al hilo hasta que quede libre.

• unlock(): Suelta el candado. Obligatorio ponerlo en el bloque finally.

• tryLock(): Mira si está libre en este nanosegundo. Si lo está, lo coge y devuelve true; si no, no espera y devuelve false (ideal para evitar Deadlocks).

• tryLock(tiempo, TimeUnit): Espera como máximo ese tiempo; si no lo consigue, desiste y devuelve false.

Salas de Espera Múltiples: Condition

Se crean desde el lock: Condition c = lock.newCondition();. Permiten separar hilos por motivo de espera (ej. Productores vs. Consumidores):

• c.await(): Equivalente a wait(). Suelta el lock automáticamente y duerme al hilo en esa sala específica.

• c.signal(): Equivalente a notify(). Despierta a 1 hilo de esa sala concreta.

• c.signalAll(): Equivalente a notifyAll(). Despierta a todos los de esa sala concreta.

▶ Ejemplo Real A: Productor-Consumidor con 2 Conditions (CintaTransportadora) cintaNoLlena y cintaNoVacia

Idea clave: Cada uno espera en la sala de lo que le falta, y al terminar toca el timbre (signal()) de la sala del otro. 

import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

public class CintaTransportadora {
    private final List cinta = new ArrayList<>();
    private final int capacidadMaxima;

    private final ReentrantLock lock = new ReentrantLock();
    private final Condition cintaNoLlena = lock.newCondition(); // Sala de espera para Productores
    private final Condition cintaNoVacia = lock.newCondition(); // Sala de espera para Consumidores

    public CintaTransportadora(int capacidadMaxima) {
        this.capacidadMaxima = capacidadMaxima;
    }

    // PRODUCTOR (AGV)
    public void ponerBateria(int idBateria) throws InterruptedException {
        lock.lock();
        try {
            while (cinta.size() == capacidadMaxima) {
                cintaNoLlena.await(); // Cinta llena: suelta lock y espera en su sala
            }
            cinta.add(idBateria);
            cintaNoVacia.signal();    // Avisa a un Consumidor de que ya hay material
        } finally {
            lock.unlock();
        }
    }

    // CONSUMIDOR (Robot)
    public int recogerBateria() throws InterruptedException {
        lock.lock();
        try {
            while (cinta.isEmpty()) {
                cintaNoVacia.await(); // Cinta vacía: suelta lock y espera en su sala
            }
            int bateria = cinta.remove(0);
            cintaNoLlena.signal();    // Avisa a un Productor de que ya hay hueco libre
            return bateria;
        } finally {
            lock.unlock();
        }
    }
}
▶ Ejemplo Real B: Cola de Prioridad Absoluta (Batería Crítica < 10%) colaCritica vs. colaNormal

Cómo dar prioridad: Usamos un contador criticosEsperando. Los hilos normales añaden || criticosEsperando > 0 en su while para ceder el paso obligatoriamente. 

private int plazasLibres = 3;
private int criticosEsperando = 0;
private final ReentrantLock lock = new ReentrantLock();
private final Condition colaCritica = lock.newCondition();
private final Condition colaNormal = lock.newCondition();

public void entrarConPrioridad(boolean esCritico) throws InterruptedException {
    lock.lock();
    try {
        if (esCritico) {
            criticosEsperando++;
            try {
                while (plazasLibres == 0) colaCritica.await();
            } finally {
                criticosEsperando--;
            }
        } else {
            // Si es normal, espera si no hay sitio O si hay algún crítico esperando
            while (plazasLibres == 0 || criticosEsperando > 0) {
                colaNormal.await();
            }
        }
        plazasLibres--;
    } finally {
        lock.unlock();
    }
}

public void salir() {
    lock.lock();
    try {
        plazasLibres++;
        if (criticosEsperando > 0) colaCritica.signal(); // Prioriza despertar urgencias
        else colaNormal.signal();
    } finally {
        lock.unlock();
    }
}
Prevención de Interbloqueos

6. Deadlock (Abrazo Mortal) y Estrategias de Solución

⚠️ ¿Cuándo ocurre un Deadlock?

Cuando dos o más hilos se bloquean mutuamente esperando un recurso que tiene el otro (ej. Hilo A tiene el Candado 1 y espera el 2; Hilo B tiene el Candado 2 y espera el 1). Ninguno avanza ni libera lo que tiene.

Las 3 soluciones clásicas de examen:

  • 1. Ordenación de recursos (Romper simetría): Todos cogen primero el recurso de ID menor y luego el de ID mayor (o el último filósofo coge derecho antes que izquierdo).
  • 2. Uso de tryLock(): Si coges el primer candado pero segundo.tryLock() devuelve false, sueltas el primero, esperas un poco y reintentas.
  • 3. Limitar acceso con Semaphore(N - 1): Si hay 5 filósofos, solo dejar sentarse a 4 a la mesa a la vez garantiza que al menos 1 siempre pueda comer.
▶ Ejemplo Real: Cena de los Filósofos (Estrategia Asimétrica con ReentrantLock) Prevención de Deadlock 
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class Filosofo implements Runnable {
    private final int id;
    private final Lock cubiertoIzq;
    private final Lock cubiertoDer;

    public Filosofo(int id, Lock cubiertoIzq, Lock cubiertoDer) {
        this.id = id;
        this.cubiertoIzq = cubiertoIzq;
        this.cubiertoDer = cubiertoDer;
    }

    @Override
    public void run() {
        try {
            while (!Thread.currentThread().isInterrupted()) {
                // Pensar
                Thread.sleep((long) (Math.random() * 200));

                // ESTRATEGIA ASIMÉTRICA: El último filósofo invierte el orden para romper el ciclo
                Lock primero = (id == 4) ? cubiertoDer : cubiertoIzq;
                Lock segundo = (id == 4) ? cubiertoIzq : cubiertoDer;

                primero.lock();
                try {
                    segundo.lock();
                    try {
                        // Comer (tiene ambos cubiertos en exclusión mutua)
                        System.out.println("Filósofo " + id + " está comiendo.");
                        Thread.sleep((long) (Math.random() * 200));
                    } finally {
                        segundo.unlock(); // Libera el segundo
                    }
                } finally {
                    primero.unlock();     // Libera el primero
                }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
