Tema 1

Programación Multiproceso

Bloque 1 · Conceptos y Gestión

1.1. Programa, Executable, Proceso y PCB

Estático

Programa

Conjunto de instrucciones escritas en un lenguaje de programación almacenadas en disco que definen la lógica de la aplicación. No consume CPU ni RAM de ejecución.

Binario

Ejecutable

Fichero en formato binario (o bytecode .class/.jar en Java) preparado para que el Sistema Operativo o la JVM pueda cargarlo en memoria.

Dinámico

Proceso

Instancia de un programa en ejecución con recursos asignados de forma independiente: espacio de direcciones de memoria aislado, registros de CPU, contador de programa y tabla de descriptores de ficheros.

🗂️ Bloque de Control de Proceso (PCB) y Aislamiento

El SO mantiene el control de cada proceso mediante una estructura de datos llamada PCB (Process Control Block), que guarda:

  • PID (Process Identifier): Identificador numérico único del proceso.
  • Estado actual: Nuevo, Listo, En ejecución, Bloqueado o Terminado.
  • Contador de programa (PC) y Registres de CPU: Qué instrucción toca ejecutar.
  • Gestión de memoria y prioridad: Límites de RAM asignada y prioridad de planificación.

⚠️ Aislamiento: Un proceso NO puede leer ni escribir directamente en la memoria de otro proceso; necesita mecanismos IPC (Pipes, Sockets, Ficheros).

🌳 Jerarquía y Tipología según Interfaz

Cuando un proceso crea a otro, se forma una jerarquía padre-hijo conocida como Árbol de Procesos. Según su interacción con el usuario se dividen en:

  • Primer Plano (Foreground): Requieren interacción directa con el usuario mediante interfaz gráfica (GUI) o consola (CLI).
  • Segundo Plano (Background) / Demonios (Daemons): Se ejecutan de forma silenciosa sin interfaz visible dando servicios al sistema (ej. servidor MySQL, servidor HTTP Apache).
Bloque 2 · Planificación y Arquitectura

1.2. Ciclo de Vida de un Proceso, Concurrencia y Comparativa

Los 5 Estados del Ciclo de Vida de un Proceso

1. Nuevo (New)

Se está creando el proceso y el SO le reserva espacio en memoria y su PCB.

2. Listo (Ready)

Tiene todo lo necesario para ejecutarse; espera en cola a que el Scheduler le dé CPU.

3. En Ejecución (Running)

La CPU está ejecutando sus instrucciones actualmente.

4. Bloqueado (Blocked)

Pausado esperando un evento externo (ej. lectura de disco, red o waitFor()).

5. Finalizado (Terminated)

Ha terminado su ejecución (normal o por error) y el SO libera su memoria.

🔄 Programación Concurrente

Múltiples tareas progresan en intervalos de temps intercalados. En un sistema con un solo núcleo, se logra alternando rápidamente entre procesos mediante el cambio de contexto (multiprogramación).

⚡ Programación Paralela

Múltiples instrucciones se ejecutan simultáneamente en el mismo instante físico aprovechando varios núcleos (multicore) o varios procesadores reales.

Comparativa Clave de Examen: Procesos vs. Hilos

Característica Proceso (Entidad Pesada) Hilo / Thread (Entidad Ligera)
Espacio de Memoria Aislado e independiente para cada proceso. Compartido (Heap) entre todos los hilos del mismo proceso.
Coste de Creación Elevado (overhead alto para el SO). Muy bajo y rápido de crear.
Cambio de Contexto Lento: requiere guardar y restaurar todo el PCB. Rápido: solo cambia registros de CPU y su pila (Stack).
Comunicación Requiere mecanismos IPC (Pipes, Sockets, Ficheros). Directa mediante variables compartidas en memoria.
Bloque 3 · Comunicación entre Procesos (IPC)

1.3. Canales Estándar, API Java y Prevención de Buffer Deadlock

Canales Estándar y Perspectiva del Padre en Java

Todo proceso nace con 3 descriptores de fichero estándar: stdin (0), stdout (1) y stderr (2). En Java, los métodos de Process se nombran desde el punto de vista del Padre:

  • p.getOutputStream() → El Padre escribe hacia el System.in del Hijo.
  • p.getInputStream() → El Padre lee lo que el Hijo imprime por su System.out.
  • p.getErrorStream() → El Padre lee los errores que el Hijo manda a System.err.
⚠️ Riesgo de Buffer Deadlock: Las tuberías usan buffers limitados del SO. Si el Hijo escribe muchos datos por stdout y el Padre llama a waitFor() antes de leerlos, el buffer se llena, el Hijo se bloquea esperando que se vacíe y el Padre se bloquea esperando que el Hijo acabe. Solución: Leer siempre antes de waitFor() y hacer flush()/close() al escribir.

Clases Principales de java.lang

ProcessBuilder (Configurador)

Prepara el comando, argumentos, directorio (directory()) y redirecciones (redirectErrorStream(true), Redirect.INHERIT) antes de arrancar con start().

Process (Proceso vivo)

Representa el proceso en ejecución. Permite obtener flujos, esperar su fin (waitFor()), consultar el código de salida (exitValue(): 0 = éxito, distinto de 0 = error) o matarlo (destroy()).

ProcessBuilder pb = new ProcessBuilder("java", "Hijo");
pb.redirectErrorStream(true); // Une stderr con stdout
Process p = pb.start();
// 1. Escribir y cerrar flujo (envía EOF)
// 2. Leer respuesta completa
int codigo = p.waitFor(); // 3. Esperar finalización

Programación Multihilo y Concurrencia

Bloque 1 y 2 · Arquitectura y Ciclo de Vida

2.1. Hilos en Memoria (Heap vs. Stack), Estados y Creación

🧠 Arquitectura en Memoria dentro de un Proceso

Cuando arranca un programa Java nace al menos un hilo principal (main). Si el proceso muere, mueren todos sus hilos. Dentro del mismo proceso:

  • Compartido entre todos los hilos: El espacio de datos/objetos (Heap), el código y los descriptores de ficheros. Si un hilo modifica un atributo de un objeto compartido, los demás lo ven.
  • Privado de cada hilo: Su propio Contador de Programa (PC), registros de CPU y su propia Pila de ejecución (Stack) para variables locales y llamadas a métodos.

🔄 Estados de un Hilo en Java

  • New: Instanciado (new Thread(...)) pero aún sin llamar a start().
  • Runnable: Tras start(), listo esperando turno del Thread Scheduler.
  • Running: Ejecutando las instrucciones de run() en la CPU.
  • Blocked / Waiting / Timed_Waiting: Pausado por sleep(), wait(), join() o esperando entrar a un bloque synchronized/Lock.
  • Dead / Terminated: Ha acabado run() (no se puede reiniciar).
Creación en Java (extends Thread vs. implements Runnable): Se recomienda implementar Runnable porque Java no permite herencia múltiple y separa la tarea del hilo. Regla crítica: Arrancar siempre con t.start() (crea el hilo paralelo en el SO); llamar a t.run() ejecuta el código secuencialmente en el hilo actual. Para esperar a que un hilo acabe se usa t.join().
Bloque 3 · Problemas Clásicos

2.2. Sección Crítica y los 4 Riesgos de la Concurrencia

Sección Crítica: Fragmento de código que accede a un recurso compartido (variable, lista, fichero) y que no debe ser ejecutado por más de un hilo simultáneamente para evitar corrupción de datos.

1. Condición de Carrera (Race Condition)

Ocurre cuando varios hilos acceden a la vez a un recurso compartido y al menos uno lo modifica sin sincronización (ej. contador++). El resultado final es impredecible y depende del orden fortuito en que el planificador de CPU intercale sus instrucciones.

2. Interbloqueo (Deadlock / Abrazo Mortal)

Dos o más hilos quedan bloqueados indefinidamente esperando cada uno un recurso que posee el otro (ej. Hilo A tiene R1 y pide R2; Hilo B tiene R2 y pide R1). Ninguno puede avanzar ni soltar lo que tiene.

3. Inanición (Starvation)

Un hilo nunca consigue acceder al recurso compartido porque otros hilos con mayor prioridad o llegada continua le adelantan sistemáticamente en la cola. (Se evita usando políticas fair / justas).

4. Bloqueo Actiu (Livelock)

Los hilos no están dormidos, sino que cambian continuamente de estado reaccionando entre sí sin lograr ningún avance real (como dos personas que intentan esquivarse en un pasillo moviéndose siempre hacia el mismo lado).

Bloque 3 · Herramientas de Sincronización en Java

2.3. Monitores, ReentrantLock, Semaphore y Variables Atómicas

A. Exclusión Mutua y Monitores Nativos

• synchronized: Adquiere el monitor intrínseco del objeto (solo 1 hilo dentro). Puede aplicarse a un método entero o a un bloque synchronized(this) más granular.
• wait(), notify(), notifyAll(): Métodos de Object (se llaman dentro de synchronized). Al ejecutar wait(), el hilo libera el candado del monitor inmediatamente y pasa a estado de espera hasta que otro hilo llame a notify() (despierta 1) o notifyAll() (despierta a todos).

B. Bloqueos Explícitos (ReentrantLock + Condition)

Alternativa moderna con control manual (lock() y unlock() siempre en finally). Sus dos grandes ventajas son:
• tryLock(): Permite intentar coger el candado sin quedarse bloqueado para siempre.
• Condition (await() / signal()): Permite crear múltiples colas de espera en un mismo lock (ej. separar productores y consumidores).

C. Semáforos (Semaphore) y Mutex

Gestiona un conjunto de permisos para limitar cuántos hilos acceden a la vez a un recurso (acquire() pide permiso y resta 1; release() devuelve 1):
• Semáforo Contador (new Semaphore(N)): Permite hasta N hilos simultáneos.
• Semáforo Binario / Mutex (new Semaphore(1)): Con solo 1 permiso actúa igual que un bloqueo de exclusión mutua estricta.

D. Variables y Clases Atómicas (java.util.concurrent.atomic)

Clases como AtomicInteger, AtomicBoolean o AtomicReference permiten realizar operaciones compuestas (como leer, sumar 1 y guardar con incrementAndGet()) en una única instrucción atómica a nivel de hardware/CPU (algoritmos CAS - Compare-And-Swap). Evitan el coste (overhead) y los bloqueos de usar synchronized o Lock cuando solo se protege una única variable.

▶ Ejemplo Rápido: Contador sin candados con AtomicInteger java.util.concurrent.atomic 
import java.util.concurrent.atomic.AtomicInteger;

public class ContadorSeguro {
    // Sustituye a un int normal + synchronized
    private final AtomicInteger visitas = new AtomicInteger(0);

    public void registrarVisita() {
        visitas.incrementAndGet(); // Operación atómica a nivel de CPU sin Race Condition
    }

    public int getTotal() {
        return visitas.get();
    }
}
