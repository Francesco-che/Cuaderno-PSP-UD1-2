Unidad Didáctica 1 · Java Process API

Programación Multiproceso

Todo lo que necesitas para resolver ejercicios prácticos de examen: cómo plantear la arquitectura Padre-Hijo, dominar cada método de ProcessBuilder y Process, y evitar bloqueos de comunicación.

1 Cómo plantear cualquier ejercicio del Tema 1 antes de programar

Paso 1 · Roles

Identifica Padre e Hijo

El Padre es el orquestador (pide datos al usuario o lee un fichero, lanza procesos y recoge resultados). El Hijo es un programa independiente con su propio main que hace una tarea concreta.

Paso 2 · Vías de Datos

args[0] vs System.in

Usa args[0] para pasar configuración fija al arrancar (ej. palabra clave "ERROR" o longitud mínima "8"). Usa tuberías (OutputStream ➔ System.in) para enviar datos variables o múltiples líneas.

Paso 3 · Protocolo

¿1 envío o en bucle?

Si el hijo lee múltiples líneas en un while ((linea = br.readLine()) != null), el Padre debe cerrar su OutputStream (close()) para enviar la señal de fin de archivo (EOF) y que el hijo salga del bucle.

Paso 4 · Cierre

Lee, Espera y Verifica

Orden estricto en el Padre: 1º envía datos y cierra salida, 2º lee toda la respuesta del hijo, 3º llama a waitFor() para recoger el código de salida (0 = OK, 1 = Error).

2 Perspectiva Padre-Hijo y Conceptos Clave de Teoría

La Regla de Oro: Todo se nombra desde el punto de vista del PADRE

Cada proceso tiene su propia memoria aislada (PCB propio). Para hablar entre ellos, el Sistema Operativo conecta tres tuberías estándar (Pipes):

PROCESO PADRE
p.getOutputStream()
El padre ESCRIBE datos hacia el hijo
p.getInputStream()
El padre LEE resultados del hijo
p.getErrorStream()
El padre LEE errores del hijo
ENVÍO DE DATOS ➔
No olvides .newLine() y .flush()
⬅ RESPUESTA NORMAL
Viaja lo que el hijo imprime con println()
⬅ CANAL DE ERRORES
O redirigido con pb.redirectError(...)
PROCESO HIJO
System.in
El hijo LEE con BufferedReader / Scanner
System.out
El hijo ESCRIBE con System.out.println()
System.err
El hijo REPORTA fallos con System.err.println()
Resumen Teórico Rápido (Preguntas cortas de examen)
Concepto Definición Clave
Programa vs Proceso Programa: estático, código en disco. Proceso: dinámico, programa cargado en RAM con su propio PID, memoria aislada y PCB (Process Control Block).
Concurrencia vs Paralelismo Concurrencia: múltiples tareas progresan intercalando turnos de CPU (cambio de contexto). Paralelismo: ejecución simultánea real en el mismo instante usando varios núcleos (multicore).
ProcessBuilder vs Runtime.exec() ProcessBuilder es el estándar actual: recibe una lista segura de argumentos, permite redirigir flujos, configurar el directorio de trabajo y gestionar el entorno. Runtime.exec() está obsoleto y falla con rutas con espacios.
Buffer Deadlock Ocurre si el hijo escribe muchos datos por stdout/stderr, llena el buffer del SO y se bloquea esperando que el padre lea, mientras el padre está bloqueado en waitFor() sin leer.

3 Estructura Base y Diccionario de Métodos (ProcessBuilder y Process)

Esqueleto Estándar para lanzar una clase Java hija en el examen

Memoriza estas dos líneas iniciales (java y classpath): evitan el típico error ClassNotFoundException al ejecutar desde IntelliJ o VS Code. 

// 1. Localizar el ejecutable java y el classpath actual del proyecto
String java = Paths.get(System.getProperty("java.home"), "bin", "java").toString();
String classpath = System.getProperty("java.class.path");

// 2. Configurar el comando y los argumentos (args[0], args[1]...)
ProcessBuilder pb = new ProcessBuilder(java, "-cp", classpath, "NombreClaseHija", "arg0");

// 3. Redirección opcional de errores (a fichero o a consola del padre)
pb.redirectError(ProcessBuilder.Redirect.INHERIT);

// 4. Arrancar el proceso
Process hijo = pb.start();

// 5. Escribir datos al hijo (si el hijo lee de System.in)
try (BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(hijo.getOutputStream()))) {
    bw.write("Texto enviado al hijo");
    bw.newLine();
    bw.flush();
} // El cierre automático envía EOF (null) al readLine() del hijo

// 6. Leer la salida del hijo (lo que el hijo imprime por System.out)
try (BufferedReader br = new BufferedReader(new InputStreamReader(hijo.getInputStream()))) {
    String linea;
    while ((linea = br.readLine()) != null) {
        System.out.println("Respuesta: " + linea);
    }
}

// 7. Esperar a que termine y obtener su código de salida (0 = éxito)
int codigoSalida = hijo.waitFor();

Detalle de cada método y ejemplo real de uso

Clase ProcessBuilder Configuración
new ProcessBuilder(String... command)

Crea el lanzador. Cada parámetro es un token del comando (sin juntar todo en un solo String).

ProcessBuilder pb = new ProcessBuilder(java, "-cp", classpath, "FiltreLog", "ERROR");
pb.start()

Arranca realmente el proceso en el Sistema Operativo y devuelve un objeto Process para controlarlo. Lanza IOException.

Process p = pb.start();
pb.redirectError(File file) / INHERIT

Envía todo lo que el hijo escriba en System.err directamente a un archivo físico o a la consola del padre.

pb.redirectError(new File("errors_filtre.log")); // Guarda errores en disco
// O bien: pb.redirectError(ProcessBuilder.Redirect.INHERIT); // Muestra en consola padre
pb.redirectErrorStream(true)

Fusiona stderr dentro de stdout. Así el padre lee tanto la salida normal como los errores por un único getInputStream().

pb.redirectErrorStream(true);
pb.directory(File dir)

Cambia la carpeta donde se ejecutará el proceso hijo (útil si el hijo busca ficheros con rutas relativas).

pb.directory(new File("src/datos"));
Clase Process y Flujos Ejecución e IPC
p.getOutputStream()

Devuelve el flujo de salida hacia el hijo (conectado a su System.in). Se envuelve en OutputStreamWriter y BufferedWriter.

BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(p.getOutputStream()));
bw.write("Hola hijo"); bw.newLine(); bw.flush();
p.getInputStream()

Devuelve el flujo de entrada desde el hijo (conectado a su System.out). Se envuelve en InputStreamReader y BufferedReader.

BufferedReader br = new BufferedReader(new InputStreamReader(p.getInputStream()));
String respuesta = br.readLine();
p.waitFor()

Bloquea al Padre hasta que el proceso hijo finalice por completo. Devuelve el código de salida (exitCode). Lanza InterruptedException.

int exitCode = p.waitFor(); // Espera y recoge 0 (OK) o != 0 (Error)
p.exitValue()

Devuelve el código de salida del hijo sin esperar. Si el hijo sigue vivo, lanza IllegalThreadStateException. Úsalo siempre después de waitFor().

p.waitFor();
if (p.exitValue() == 0) { System.out.println("Todo correcto"); }
p.destroy() / System.exit(int)

p.destroy() mata al hijo desde el padre. En el hijo, System.exit(0) indica éxito y System.exit(1) indica error.

if (texto.isEmpty()) { System.err.println("Vacío"); System.exit(1); }

4 Ejemplos Reales Completos (Patrones de Examen)

🎯 Patrón A: Conversación ida y vuelta por turnos (Concurso Matemático - Ej. 8) Ver / Ocultar
¿Cuándo sale este patrón? Cuando el Padre envía varias preguntas o líneas una a una y necesita leer la respuesta del hijo en cada iteración del bucle.
Clave técnica: Dentro del bucle for, el Padre hace write() + newLine() + flush() y justo después readLine(). El hijo usa PrintWriter(..., true) (con autoFlush) para que su respuesta salga inmediatamente sin quedarse atascada en el buffer.
1. ConcursoHijo.java
import java.io.*;

public class ConcursoHijo {
    public static void main(String[] args) throws IOException {
        BufferedReader entrada = new BufferedReader(new InputStreamReader(System.in));
        // autoFlush = true para que cada println() viaje al padre al instante
        PrintWriter salida = new PrintWriter(new OutputStreamWriter(System.out), true);

        String operacion;
        // Lee línea a línea hasta que el Padre cierre el stream (null)
        while ((operacion = entrada.readLine()) != null) {
            if (operacion.contains("+")) {
                String[] partes = operacion.split("\+");
                int res = Integer.parseInt(partes[0]) + Integer.parseInt(partes[1]);
                salida.println(res);
            } else if (operacion.contains("*")) {
                String[] partes = operacion.split("\*");
                int res = Integer.parseInt(partes[0]) * Integer.parseInt(partes[1]);
                salida.println(res);
            }
        }
    }
}
2. ConcursoPadre.java
import java.io.*;
import java.nio.file.Paths;
import java.util.Random;

public class ConcursoPadre {
    public static void main(String[] args) throws Exception {
        String java = Paths.get(System.getProperty("java.home"), "bin", "java").toString();
        String cp = System.getProperty("java.class.path");

        ProcessBuilder pb = new ProcessBuilder(java, "-cp", cp, "ConcursoHijo");
        pb.redirectError(ProcessBuilder.Redirect.INHERIT);
        Process hijo = pb.start();

        BufferedWriter salida = new BufferedWriter(new OutputStreamWriter(hijo.getOutputStream()));
        BufferedReader entrada = new BufferedReader(new InputStreamReader(hijo.getInputStream()));

        Random rand = new Random();
        int aciertos = 0;

        for (int i = 1; i <= 5; i++) {
            int a = rand.nextInt(9) + 1;
            int b = rand.nextInt(9) + 1;
            String op = a + "+" + b;

            // 1. Padre -> Hijo
            salida.write(op);
            salida.newLine();
            salida.flush(); // Obligatorio para empujar el dato en cada vuelta

            // 2. Hijo -> Padre
            int respHijo = Integer.parseInt(entrada.readLine());
            if (respHijo == (a + b)) aciertos++;
        }

        // 3. Cerrar streams FUERA del bucle para que el hijo salga de su while
        salida.close();
        entrada.close();
        hijo.waitFor();

        System.out.println("Aciertos: " + aciertos + "/5");
    }
}
🚀 Patrón B: Pipeline Paralelo con 2 Hijos, Argumentos y Control de Errores (Práctica LogAnalyzer) Ver / Ocultar
¿Cuándo sale este patrón? En ejercicios de nivel completo donde el Padre lanza varios procesos hijos en paralelo pasándoles parámetros por args[0], redirige errores a un fichero y verifica los exitValue().
Clave técnica: Se arrancan ambos hijos con .start(), se les envía el bloque de texto y se cierra su BufferedWriter (try-with-resources) antes de leer sus respuestas y llamar a waitFor().
1. FiltreLog.java (Proceso Hijo)
import java.io.*;

public class FiltreLog {
    public static void main(String[] args) throws IOException {
        // 1. Recibe la palabra a buscar por argumento (por defecto "ERROR")
        String palabra = (args.length > 0) ? args[0] : "ERROR";

        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int contador = 0;
        boolean tieneContenido = false;
        String linea;

        while ((linea = br.readLine()) != null) {
            if (!linea.trim().isEmpty()) tieneContenido = true;
            if (linea.contains(palabra)) {
                contador++;
            }
        }

        // 2. Si el texto estaba vacío, reporta por stderr y sale con código 1
        if (!tieneContenido) {
            System.err.println("Error: Texto vacío recibido.");
            System.exit(1);
        }

        // 3. Imprime resultado por stdout y sale con código 0
        System.out.println(contador);
        System.exit(0);
    }
}
2. AnalitzadorPrincipal.java (Proceso Padre)
import java.io.*;
import java.nio.file.Paths;

public class AnalitzadorPrincipal {
    public static void main(String[] args) throws Exception {
        String logs = "2026-09-30 INFO Inicio\n" +
                      "2026-09-30 ERROR Fallo disco\n" +
                      "2026-09-30 WARNING Memoria alta\n" +
                      "2026-09-30 ERROR Timeout\n";

        String java = Paths.get(System.getProperty("java.home"), "bin", "java").toString();
        String cp = System.getProperty("java.class.path");

        // Configuramos dos hijos con distintos args[0]
        ProcessBuilder pbErr = new ProcessBuilder(java, "-cp", cp, "FiltreLog", "ERROR");
        ProcessBuilder pbWarn = new ProcessBuilder(java, "-cp", cp, "FiltreLog", "WARNING");

        // Redirigimos stderr a fichero físico
        pbErr.redirectError(new File("errors_filtre.log"));
        pbWarn.redirectError(new File("errors_filtre.log"));

        // 1. Arrancamos ambos procesos en paralelo
        Process hErr = pbErr.start();
        Process hWarn = pbWarn.start();

        // 2. Enviamos datos y cerramos flujos (try-with-resources hace close() solo)
        try (BufferedWriter outErr = new BufferedWriter(new OutputStreamWriter(hErr.getOutputStream()));
             BufferedWriter outWarn = new BufferedWriter(new OutputStreamWriter(hWarn.getOutputStream()))) {
            outErr.write(logs);
            outErr.flush();
            outWarn.write(logs);
            outWarn.flush();
        }

        // 3. Leemos resultados
        String resErr, resWarn;
        try (BufferedReader inErr = new BufferedReader(new InputStreamReader(hErr.getInputStream()));
             BufferedReader inWarn = new BufferedReader(new InputStreamReader(hWarn.getInputStream()))) {
            resErr = inErr.readLine();
            resWarn = inWarn.readLine();
        }

        // 4. Esperamos finalización y comprobamos exitValue()
        hErr.waitFor();
        hWarn.waitFor();
        int exitFinal = (hErr.exitValue() == 0 && hWarn.exitValue() == 0) ? 0 : 1;

        System.out.println("RESULTAT: ERRORS=" + resErr + " | WARNINGS=" + resWarn + " | EXIT_CODE=" + exitFinal);
    }
}

⚠️ Checklist Anti-Bloqueos antes de entregar tu código del Tema 1

  • 1. ¿Pusiste bw.newLine() y bw.flush() después de cada bw.write()? Sin salto de línea, el readLine() del hijo se queda esperando eternamente.
  • 2. ¿Cerraste el OutputStream del padre (close()) antes de esperar la respuesta final cuando el hijo lee con while ((l = br.readLine()) != null)?
  • 3. ¿Leíste getInputStream() antes de llamar a waitFor()? Si el hijo imprime mucho texto y llamas antes a waitFor(), llenarás el buffer y bloquearás ambos procesos.
  • 4. ¿Cerraste los streams fuera de los bucles? Cerrarlos dentro provoca IOException: Stream closed en la segunda vuelta.
